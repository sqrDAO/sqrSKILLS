# web3-opportunities validation split

## Goal

Extend the gated skill-improvement loop to the second skill that can support it.
`web3-opportunities` is the only remaining skill whose ground truth can be
generated rather than typed: an offline roster plus a deterministic query script,
no network and no credentials. Five of the ten skills here call live APIs,
`vietnam-crypto-radar` ships no script, and `business-model-to-market` produces a
workbook rather than an answer — see `evals/README.md` for why a hand-written
answer key is worse than no split at all.

The split is built and calibrated. What remains is the baseline run, which needs
one fresh agent per case and is therefore a deliberate spend, not a side effect
of this spec.

## Files

- `evals/scripts/rubric.py` — shared grading machinery, extracted from
  `grade_visa.py`: negation-aware `forbid_all`, run-completeness refusal, the
  summary shape. Four rounds of corrections that should exist once, not twice.
- `evals/scripts/build_web3_cases.py` — 24 cases across 8 probe families. Truth
  and the two rot-prone rubric patterns (`<DATA_AS_OF>`, `<TRUTH_COUNT>`) are
  generated by running `query_opportunities.py`.
- `evals/scripts/grade_web3.py` — expected calls are facet constraints, not
  literal command lines; argv is normalised by the skill's own script.
- `evals/web3-opportunities/cases.jsonl`, `wiki/` — 8 predicted patterns, each
  recorded as an unfalsified hypothesis before the run that can falsify it.
- `evals/scripts/grade_visa.py` — refactored onto `rubric.py`.
- `tests/test_evals_harness.py` — 24 tests over the grading machinery.
- `.github/workflows/test.yml` — both `--check` staleness runs.
- `AGENTS.md`, `evals/README.md` — the loop was undocumented outside `evals/`.

The last command must still report `pass_rate: 1.0` — it is the regression check
on the shared-module extraction.

## Notes

The `vietnam-visa-check` split is saturated at 24/24 and is a retirement
candidate, not a live gate. Expect the same arithmetic here as there: four rounds
of corrections to the harness against three rounds of edits to the skill. The
thing doing the measuring is wrong more often than the thing being measured, and
the first round of that has already happened — a `forbid_all` written as a phrase
failed a correct answer during calibration.
