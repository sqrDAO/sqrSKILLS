# p010 — an organisation name is not a facet

**Status:** observed in iter0, **not reproduced in iter1** (2026-08-29). Not predicted.
**Probes:** w3o-07 (`search-facet`) — call failed, answer passed.

## What happened

The prompt was "Does Optimism fund anything? What exactly?" The agent ran
`--type grant`.

That query returns `optimism-grants` and cannot return `optimism-retro-funding`,
which is `type: retroactive_funding`. The answer nonetheless described both,
correctly, including the pause until 2027 — so the roster-shaped half of the
answer came from somewhere other than the query the agent ran.

`--search optimism` returns exactly the two entries and is in the Usage block as
a worked example. The tool was documented and sitting right there.

## Root cause

Step 1 of the core method says "Query the bundled roster **with the user's
facets**". The user did not supply a facet. They supplied an organisation, and
the six facets have no slot for one. Faced with a query that does not decompose
into the documented shape, the agent picked the nearest facet it could infer —
`grant` from "fund" — rather than the free-text search built for this case.

## Why this matters less than it looks, and more

Less: the user got a correct and complete answer. `answer_score` passed.

More: the correctness is unearned. A question about which programmes an
organisation runs was answered without asking the catalog that question, and the
gap was closed by live search and recall. That is the p006 failure mode wearing
better clothes — the answer is right this time, and there is no mechanism here
that would make it right the next time. It is also invisible to anyone reading
the reply, which is what makes it worth a case at all.

## iter1: it did not happen again

Same prompt, same skill text apart from an unrelated edit, and the agent ran
`--search optimism` — retrieving both entries, exactly the behaviour the case
wants. Nothing in E1 touches facet selection, so this is not the edit working.

One agent reaching for `--type grant` and another reaching for `--search`, on
identical instructions, is variance. Two observations of a coin do not establish
a bias, and treating the first one as a defect would have bought an edit to
`SKILL.md` paid for by noise.

## Proposed fix — withheld

E2 stays unapplied. It needs repeats to distinguish a documentation gap from a
coin flip, and this split has one repeat per iteration. That is a limitation of
the split, and the right response is to fix the split rather than to guess.
