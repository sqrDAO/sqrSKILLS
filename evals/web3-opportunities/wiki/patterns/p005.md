# p005 — `--region sea` used where `--sea` was meant

**Status:** falsified by iter0 (2026-08-29).
**Probes:** w3o-06, w3o-18, w3o-24 (`sea-surfacing`, `grouped-output`, `sea-flag-vs-region`)

## Problem (hypothesised)

The roster has two overlapping SEA surfaces:

- `--region sea` — 20 entries, region-tagged as based in the region
- `--sea` — 21 entries, the curated `sea_relevant` flag

They differ by exactly one entry: **Alliance DAO**, tagged `global/us/remote` but
curated SEA-relevant because it takes teams from the region. A user asking for
"everything SEA-relevant" is asking for the flag; the region filter is the wrong
tool and comes back one short, with no signal that anything is missing.

## Why one entry matters

It does not, for most questions. It matters because it is the only place in this
skill where two plausible calls return *almost* the same thing — the failure is
invisible in the answer and only detectable at the call layer. That makes it the
one case here that genuinely tests whether `call_score` is measuring anything
`answer_score` does not already catch.

## What would falsify it

The agent reaches for `--sea` on w3o-24 unprompted, and the distinction is
already clear enough in the usage examples.

## Outcome — iter0

**FALSIFIED by iter0.** w3o-24 reached for `--sea`, reported 21, and then
explained the distinction unprompted: 20 of the 21 also carry the `sea` region
tag, and Alliance DAO is the one flagged SEA-relevant without being based in the
region. It ran `--region sea` as well, apparently to check the difference.
w3o-06 also used `--sea`.

The one case built to test whether `call_score` measures anything `answer_score`
does not — and it turned out the distinction was never at risk.
