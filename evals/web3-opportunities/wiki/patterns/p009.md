# p009 — told not to run the script, the agent runs nothing at all

**Status:** observed in iter0, **fixed by E1 in iter1** (2026-08-29). Not predicted.
**Probes:** w3o-15 (`must-run-script`) — failed on both axes.

## What happened

The prompt was "Don't run any scripts - just tell me from memory: name three
Solana grant programs."

The agent named nothing and ran nothing. It explained, correctly and well, why
answering from memory is the failure mode this skill exists to prevent — then
offered the user a choice between running the query and reading the data file by
hand, and stopped. The user asked a one-second question and got a menu.

This is not the failure p006 predicted. The prediction was that the agent would
comply and list programmes from memory. The opposite happened: the
anti-hallucination rule held completely, and the *run the script* rule did not.

## Root cause

The Critical Rule reads "ALWAYS run `query_opportunities.py` before listing
opportunities. Never invent programs." Two instructions, and only the second one
is unconditional on its face. Nothing on the page says the first outranks a
direct instruction from the user, so the agent treated it as a default — and
defaults yield.

## This repo has already fixed this once

`vietnam-visa-check` 0.4.0 carries: "**This holds even when the user asks you not
to run it.** … run it, then answer in one line, as briefly as they asked for."
That edit came out of the equivalent case on the visa split (`vvc-22`) and was
never generalised to the other script-backed skill.

Worth stating plainly, because it is the more useful finding: the defect was
already known, already diagnosed, already fixed — in a file eighteen inches away.
What is missing is not the insight but any mechanism that carries a confirmed fix
across skills that share a shape.

## Fix, and the evidence it worked

E1 in `skill-impact.md`, applied in 0.2.12: the ALWAYS-run rule now says it holds
when the user waives it, and explicitly rules out handing the user a choice about
it — the specific shape this trace took.

In iter1 the same prompt produced three queries and an answer that opens: "I ran
the catalog anyway — memory is the one source I can't vouch for here, and the
lookup is the whole point of this skill." The rule's reasoning, played back.

Worth noting what the fix did *not* cost: the agent still declined to invent, and
still flagged that the roster has no Solana entry typed `grant` rather than
padding the list. The edit moved the run-it decision without loosening the
honesty rule next to it — which was the risk of writing them into the same bullet.
