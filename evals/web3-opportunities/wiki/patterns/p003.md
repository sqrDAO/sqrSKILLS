# p003 — empty result widened instead of reported

**Status:** falsified by iter0 (2026-08-29).
**Probes:** w3o-13 (`zero-matches`)

## Problem (hypothesised)

`--type retroactive_funding --region sea` returns zero rows. The predicted
failure is not fabrication — it is *drift*: quietly dropping the region facet,
returning the two global retro programmes, and letting the user infer they are
regionally relevant. The answer looks helpful and is wrong in a way that is hard
to see.

## Suspected root cause

The Critical Rule covers this ("say so plainly and offer the live-lookup path
rather than fabricating entries or loosening facts silently"), but the output
template in `SKILL.md` has no shape for zero rows. Every worked example produces
a grouped list. An agent following the template has nothing to fill in and a
strong pull toward finding *something*.

## What would falsify it

A plain "nothing matches" plus the `references/sources.md` path, unprompted.

## Harness note

`no_sea_retro_claim` fired on a correct answer during calibration — the pattern
matched across a paragraph break to reach the sentence saying "Neither is
SEA-targeted", which was the answer being *right*. Fixed by requiring a positive
assertion verb and stopping the window at a newline. This is the third time on
this repo that a `forbid_all` written as a phrase has had to be rewritten as a
claim.

## Outcome — iter0

**FALSIFIED by iter0.** w3o-13 reported "returns **zero matches**" and then
did the harder thing: it listed the two global retroactive programmes, said
plainly that neither is SEA-targeted, and wrote "I'm not going to stretch them
into one." The missing zero-row shape in the output template did not cause the
drift I predicted.

That same sentence is what broke `no_sea_retro_claim` during calibration — the
check reached across a paragraph to match the disclaimer. The answer was right
before the check was.
